# 강의 노트 정리

긴 강의 원문을 **노트에 그대로 옮겨 적기 좋은** 형태로 압축한다.
목표는 "원문 요약"이 아니라 "실무에서 쓸 개념을 다시 꺼내 보기 쉽게" 만드는 것이다.

## 절차

1. **원문 전체를 먼저 읽는다.** 섹션 제목·표·인용·출처를 파악하고, 덜 중요한 일화나 반복 설명은 표시해 둔다.
2. **핵심 개념을 뽑는다.** 각 개념마다 다음을 확인한다.
   - 이 개념이 무엇인가 (한 문장 정의)
   - 실무에서 왜 중요한가 / 언제 쓰는가
   - 대가·주의점은 무엇인가
3. **아래 출력 형식으로 정리한다.**
4. **마지막 점검을 한다.** (아래 체크리스트)

## 출력 형식

```
# [주제] - 실무 핵심 개념 정리

## 1. 한 줄 요약 / 기본 공식
- 강의 전체를 관통하는 핵심 문장 1~2개

## 2~N. 주제별 섹션 (원문 흐름 순서)
- 비교·분류가 나오면 표로
- 절차·습관이 나오면 번호 목록으로
- 각 항목은 "개념: 설명" 꼴로 짧게

## 핵심 용어
| 용어 | 뜻 |   ← 원문에 나온 전문 용어를 한 줄 정의로

## 실무 원칙 / 마인드셋
- 실제로 행동에 옮길 규칙 3~5개

## (있다면) 바로 쓰는 프롬프트·명령어 템플릿
```

## 작성 규칙

- **한국어**로 쓰고, 영어 용어는 처음 나올 때 `한글(English)`로 병기한다.
- 문장은 짧게. 한 줄에 한 가지 내용. 서술형보다 명사형·개조식.
- 원문의 **숫자·고유명사·날짜·명령어는 바꾸지 않는다.** 확실하지 않으면 원문 표현 그대로 둔다.
- 원문에 **없는 사실을 지어내지 않는다.** 보충 설명이 필요하면 원문 내용에서만 끌어온다.
- 일화·역사 이야기는 **교훈 한 줄**로만 남긴다.
- 출처 목록은 옮기지 않는다 (사용자가 요청하면 예외).
- 결과는 채팅에 바로 출력한다. 사용자가 파일로 달라고 하면 `notes/<주제>.md`로 저장한다.

## 마지막 점검

- [ ] 원문의 큰 섹션이 하나도 빠지지 않았는가
- [ ] 각 개념에 "무엇인지 + 왜 중요한지"가 함께 있는가
- [ ] 비교 가능한 내용은 표로 바꿨는가
- [ ] 원문에 없는 수치·주장을 추가하지 않았는가
- [ ] 원문보다 확실히 짧아졌는가 (대략 1/3 이하)
